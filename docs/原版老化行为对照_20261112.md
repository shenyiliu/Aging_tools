## 已知非 1:1 项和未闭合问题

1. **界面与范围**：按需求保留现有界面结构，去掉账号、后管及非老化入口，不做像素复刻；原工具的账号、OA3、下载注册与系统部署分支不进入老化宿主。
2. **启动与清理**：直接协调引擎，不再把原包装器当生产入口；不执行原未知注册命令、卸载/清理分支，不全局按映像名杀其他任务，不清系统事件日志，不关闭 UAC。
3. **BurnIn 启动**：新宿主运行冻结 bit.exe 的 `-P -S <run.bits>`，加载相同模式配置，明确关闭前后置动作、设置独立 TEXT 报告和完整目标时长；不复制原 `/d` 少1分钟和窗口快捷键停测。结果要求本轮总体标记、时长及所选全部启用测试的有效操作与零错误，不再只看局部 CPU/内存行。Temperature 监测行可能无操作计数，不能把它当压力项目要求非零操作。
4. **FurMark 时长与结果**：使用完整目标 h×3600 秒，修复动态背景拼错参数并启用 GPU 日志；首次6分钟验证证明默认稳定模式下 `/max_time` 单独无效，需要显式定时模式，不能把420秒超时记成6分钟成功。修复后的模式与原稳定模式/外层强退有差异。实际窗口客户区可能小于传入尺寸。目前没有经过确认的硬件稳定性 PASS 合同，只有时间与采样证据时返回 Uncertain。官方冻结版本为1.30.0.0，身份见组件清单；生产商业/分发授权仍须补齐。
5. **3DMark 计时**：原恢复的 `+4294967266` 语义/单位仍未闭合，不能宣称已准确复刻原始倒计时。新实现按完整用户目标，采用 `--loop=1` 逐完整场景重复，到目标后不再开启新轮，故可能超过目标一个场景；单轮设置1小时上限。新增 `--out/--export/--log` 只由当前3DMark2官方文档支持；3DMark11兼容性、SystemInfo/DLC、合法商业授权与冻结版本均需补齐实测。
6. **XML 与自动恢复修复**：兼容 Time Spy `is_windowed`；续测使用任务/用户/路径/系统启动身份绑定及去重，不沿用原 Startup 快捷方式与先计数后重启方式。
7. **结果更严格**：缺报告、报告早于本轮、提前退出、用户中止、设备不支持或纯模拟均不能产生硬件通过。原 UI 以错误数汇总的 PASS 不能直接映射为新宿主硬件通过。
8. **验证边界**：本文为静态恢复与实现对照，未运行原包装器进行行为轨迹比较；Reboot、S3/S4/CS、风扇和跨启动续测需要专机实测。当前电脑的正式界面负载/视频运行结果由验收记录另行报告，不在本文预先宣称成功。
