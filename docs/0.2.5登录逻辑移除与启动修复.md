# 0.2.5 登录逻辑移除与启动修复

## 问题与原因

依赖预检把全队列的登录续测条件重复应用于每个项目。启动时查询尚不存在的计划任务，Windows 返回 System.IO.FileNotFoundException (0x80070002)，原代码只捕获 COMException，导致执行前报错。本机通过只读查询已复现与截图一致的异常。

## 修复行为

- 移除登录续测配置项、计划任务查询/注册、启动与重启前登录任务强制验证。
- 依赖预览仅检查项目自身组件和系统能力；实际执行仍检查管理员权限、系统能力和引擎依赖。
- 重启前保存检查点。开机后手动打开工具，点击“恢复任务”；旧 --resume 参数也不自动执行硬件。
- 保留启动 GUID 校验，同一次开机重开软件不增加周期；下次开机开始仍等待真实开机变化。
- 旧 options.json 和检查点中的 ResumeAtLogon 字段可读取但不再生效。卸载仅保留对本安装目录旧续测任务的定向清理。
- 系统不支持 S3 和缺失引擎仍如实阻止对应项目，不以移除登录检查绕过。

## 验证

验证完成后记录实际结果。本次不执行物理重启、睡眠或新的压力负载，之前六分钟 BurnIn 实测证据保留。
