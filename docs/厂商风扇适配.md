# 厂商风扇脚本适配

依据：原版 Reboot.au3 18936–18985 的风扇调用和结果解析，以及 GW_TEST/Reboot/cpufan/IP3、WB、Ed 中的 CPUFUN.cmd。仅用户在 Reboot 项目显式选择方案时执行；方案 N 不调用风扇组件。不自动猜测主板或对所有机型运行 EC 命令。

## 复用与执行

WindowsPlatform.PrepareCycleAsync 在重启前阶段调用 FanTestAdapter；HostPlatform 转发该调用。Core 的倒计时/续测策略负责等待准备完成。预检要求管理员、已核对的原脚本 SHA256 和方案所需组件。脚本哈希变化或组件缺失时阻止执行，不能将未知版本套用已知恢复命令。

脚本和依赖复制到本轮唯一 ProgramData/GW.AgingTool/fan-work 目录；不复制旧 TXT/LOG。原脚本中的 del *.txt 只会作用于这个副本，不触及原组件和用户日志。执行通过 OwnedProcessRunner 归入本任务 Job Object。

原 CPUFUN.cmd 保持原样。仅对其哈希核对通过的私有 CPUFUN.runtime.cmd 作如下修正并随本轮报告归档：

- 将明确的 timeout /t N 行替换为 Windows PowerShell Start-Sleep，避免无控制台/重定向导致等待被跳过。
- WB/Ed 的 if ... set errmsg=... & goto fail 改成条件括号块，避免 goto fail 无条件执行；Ed 两处缺少 set 的 errmsg 赋值同时修正。没有其他不受限文本替换。

## 读数和判定

保持原宿主的聚合规则：IP3 用 fanr1/fanr2 末尾的两个十六进制字节拼接为阶段 1 RPM，fanr3/fanr4 为阶段 2 RPM；WB/Ed 分别将两次十进制读数平均、四舍五入。完整保留四份原始读数。

同时检查原脚本的阈值：IP3 阶段 1 大于 3000 且不超过 7000，阶段 2 大于 5300；WB/Ed 的第二份高档读数至少 5000，第四份低档读数 2000–4000。错误文件、非零退出、缺失/非数值/非正数读数均失败。原宿主错误查找 CPUFAN/Error.txt（漏方案子目录），新实现检查本轮副本中的 Error.txt，避免漏判脚本失败。

## 自动模式恢复

运行完成、异常或用户取消均在 finally 中调用独立的恢复路径，恢复不使用已取消的 Token。WB 执行 wbFanTool.exe /set 0；Ed 执行 Rw.exe -c（包内 Readme 明确为退出测试、回正常模式）；IP3 执行原成功/失败尾部的两组共 12 次寄存器写入，保留组间/结束各 2 秒等待。每个恢复进程上限 8 秒，逐步保留 stdout/stderr；非零退出、明显错误输出或启动异常使本轮失败，提示人工核查，不判通过。

调用成功仅证明恢复命令完成；原工具没有统一的跨厂商自动模式回读接口，仍需在对应主板上验收真实恢复。宿主崩溃、断电等无法运行 finally 的情况同样需要硬件/专机恢复验证，不能把软件策略描述成硬件已保证。

本轮仅完成静态分析、软件解析/执行策略测试，未在当前机器运行任何风扇脚本、EC 写入或恢复命令。对应原始组件保留，不安装驱动、不关闭系统防护来绕过不兼容。
