# 0.2.4 安装错误 32 修复记录

日期：2026-11-11。

## 现场问题

用户安装 0.2.3 时，目标为 C:\Program Files\GW Aging Tool\Test.exe，DeleteFile 返回 32（共享冲突）。现场 Restart Manager 查询指向系统 SNMPTrap 服务，PID 8068，显示名“SNMP 陷阱”。没有发现老化工具 Test.exe 进程在运行。没有停止该服务，也没有关闭安全软件。

两份安装日志显示：首次安装曾继续完成，但启动旧 Test.exe 时 CreateProcess 也返回 32；第二次重装停在替换该文件。已安装的 Test.dll 等文件时间已更新，而 Test.exe 仍为旧时间，说明存在混合版本风险。程序互斥体只能检测本工具实例，不能覆盖系统服务或其他程序持有的文件句柄。

## 修复

- 在 Inno Setup PrepareToInstall 阶段递归检查目标目录文件能否以写入及删除权限打开，OPEN_EXISTING、不修改文件内容。
- 检查不要求独占读取。只读仍可成功、但禁止覆盖/删除的句柄，也会被检出。
- 发现占用或权限问题立即返回路径和 Windows 错误码，写入 GMK_INSTALL_LOCK_BLOCKED 日志，阻止开始复制程序文件。
- 安装目录页始终显示。旧目录持续被系统服务占用时，可选择新的空目录；用户数据仍在原 %LOCALAPPDATA%/GW.AgingTool，不随安装路径迁移。
- 沿用 GMK 名称、官方 Logo 和固定正式 AppId。没有执行真实重启、睡眠、风扇或追加压力测试。

这是安装前检查。若文件在检查结束后才突然被外部进程锁住，Windows 仍可能拒绝替换；不能承诺外部进程永远不会再次锁文件。

## 自动验收方式

scripts/verify-installer-isolated.ps1 使用独立随机 AppId、当前用户安装和临时中文/空格目录，调用同一份安装脚本及完整发布文件。QA 包只改变安装标识、压缩及快捷方式范围，不替换正式安装或用户数据。

流程包括 0.2.3 文件安装、真实文件锁下升级被拦截且文件哈希不变、释放后升级、逐文件哈希、内置运行时与组件发现、安装后界面演练、两个 Worker 测试、运行中升级/卸载保护、卸载保留用户数据及只清理本安装的测试续测任务。测试锁覆盖主 EXE、DLL 和嵌套 BurnIn EXE，复现 FILE_SHARE_READ 允许读取但拒绝替换的行为。

实际运行结果与通过范围以 artifacts/verification/installer-isolated-0.2.4-*/result.json 为准；文件不存在表示该次验收没有完成。单元测试及软件 E2E 在 artifacts/verification/installer-fix-0.2.4 中。此记录不等同于全用户实际安装或其他机型验收。

## 当前机器安装建议

先取消仍停在报错处的旧安装器，切勿跳过文件。使用 0.2.4 安装到新的 C:\Program Files\GMK Aging Tool 空目录，可避开旧 Test.exe 的现有占用；或由管理员查明并释放 SNMPTrap 的占用后在原目录安装。不要强制结束系统服务，也不要用旧新程序文件混装的目录继续老化测试。
