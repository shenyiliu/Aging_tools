# 目标机测试与修复（0.3.3）

日期：2026-11-13，Asia/Shanghai。目标：192.168.18.57 / DESKTOP-UIC2GKR；GMKtec EVO-X2，AMD Ryzen AI Max+ 395 / Radeon 8060S，32 GB 可用物理内存，Windows 11 专业版 10.0.26300，显示驱动 32.0.32015.12012。

## 已复现与修复

1. 首次执行 `--compatibility-report` 时，旧实现直接使用空 AppOptions，误报安装内已有的 PwrTest、BurnIn 和视频缺失。新实现与正式界面共用组件路径解析，并仅在内存中迁移路径，不创建数据目录或改写配置；保留显式外部覆盖。
2. 工具栏关闭时先释放背景图片、后销毁按钮，消息处理期间重绘可触发 `System.ArgumentException: Parameter is not valid`。调用栈为 `Image.get_Flags → ControlPaint.IsImageTransparent → ButtonFlatAdapter.PaintBackground`。修复为先停止回调、销毁控件，最后释放图片并清空缓存；新增检查实际按钮销毁时图片仍可访问的回归。
3. 测试程序现在保存未经处理的 UI 异常调用栈并失败退出；真实 BurnIn 非通过也返回失败退出码，避免仅凭进程退出码误认验收通过。
4. S3/S4 的混合睡眠参数曾传为 `/h:0`，目标机随包 PwrTest 帮助只接受 `/h:y`、`/h:n`；已转换为正确语法，并使用 `/d:0`，避免宿主倒计时后额外等待 PwrTest 默认 90 秒。睡眠报告新增原始事件 JSON，核对本轮配对事件、实际 S3/S4 状态与目标时长。
5. 新增可单独选择的 DDR Test（BurnIn mode 3），使用保留原配置作为基础，再通过脚本选择标准循环内存测试、100% 内存占空比和 `RUN MEMORY`，不并行运行 CPU/GPU/磁盘负载。要求本轮内存操作数大于零、零错误、足够时长；允许 Temperature 传感器诊断行，拒绝其他压力负载结果行。不覆盖 Windows 不可用的保留内存。第一次独立 DDR 原始报告通过，但程序误把 Temperature 当成额外压力项并判失败，此解析错误已修复，旧失败证据保留。
6. 目标机首次压力验收计划任务继承后台低优先级；验收任务和正式重启续测任务改为正常优先级。
7. 原版六分钟 BurnIn 在 09:43:24.618 因 Idle Timeout 进入 Modern Standby（Kernel-Power 506），直到 10:07:59 / 10:08:30 才退出，中断了实际负载和 SSH。修复为真实压力或视频执行期间持有 Display/System/Execution 电源请求，结束、取消或失败时自动释放，不修改全局电源方案。S3/S4/Reboot 不持有此请求；目标机已确认运行中三项请求均由本轮 Test.exe 持有。
8. 0.3.2 实际重启后目标 Windows 的 `SystemBootEnvironmentInformation` GUID 与重启前相同，导致登录任务虽然自动拉起正式 Test.exe，程序仍判为同次开机，周期保持 0/1。系统 Kernel-General 12 记录号从 1879 变为 2232，启动时间从 09:03:28 变为 11:01:59，确认发生真实重启。0.3.3 改用持久化的内核启动事件记录号与 StartTime 作为启动标识；同次开机稳定、时钟调整不重算，缺失或无效事件禁止自动计数。旧 GUID 与新格式不能比较，旧检查点不会因升级而误增周期，需保留日志并新建测试任务。
