## BurnIn 桥的真实执行路径

仅支持原目录里的 bit.exe 文件版本 9.2.1006.0，模式 0/1/2 分别读取同目录 LastUsed_0/1/2.bitcfg。将引擎及选定配置复制到本轮专用工作区，生成真实 `.bits` 脚本，使用副本的 `bit.exe -P -S <脚本>` 启动。工作区限制为当前用户、管理员和 SYSTEM 可访问，采用 ASCII 路径，最终将报告和脚本保留到用户本轮日志目录，清理临时引擎及授权副本。

脚本设置测试时长（小时转换为分钟）、关闭按周期提前停止、覆盖加载配置里的前后置外部动作、开启本轮独立文本报告、执行 RUN CONFIG 后 EXIT。进程由现有 Job Object 管理，停止关闭本任务的进程树。程序不生成引擎 PASS 报告。

判定需同时满足：引擎正常退出；本轮唯一目录里存在引擎报告；报告有明确 TEST RUN PASSED；报告中的实际测试时长达到目标的 95%；报告有对应 CPU/内存或磁盘结果行。明确失败返回 Fail，缺少结果/时长/测试行返回 Uncertain。脚本、所选配置、引擎版本与 SHA256、原始结果及 stdout/stderr 均保存。

命令依据为 PassMark 官方《BurnInTest V11 用户指南》的脚本/命令行章节，及包内 V9 Readme 的兼容说明。用户授权后已对原 9.2 引擎实际执行模式 0：脚本解释成功、CPU/GPU/内存等实际运行，报告为 6 分 04 秒；磁盘行返回 FAIL，整轮如实记为失败。首次执行发现原引擎还会写自身默认文件，因此后续改为隔离副本执行；隔离逻辑有软件回归，尚未再次执行完整负载短测。详见《真实短测结果_20261110》。官方文档：https://www.passmark.com/downloads/BIT_Users_Guide_Ed11.pdf 。

## 必须继续完成的功能

FurMark 与 3DMark 的原包装器/可运行引擎仍不完整，当前没有内置可交付适配；不能通过把模板的 Verified 改为 true 解决。Core Temp 温度桥、厂商风扇、断电及跨重启的目标机验收也未完成。SFT/SN 工具为外部调用，需选择真实文件。

软件测试验证报告判定、模拟隔离、检查点、进程管理与 UI 流程；实际模式 0 短测是另外的硬件证据。发布整套可用工具前，还需要完成 BurnIn 其他模式和隔离副本短测、用户停止、错误/提前退出、视频真实播放与 P/F、Reboot/S3/S4/CS 支持项 3 轮，再进行长稳及多机型验证。本轮按授权执行了 BurnIn 及其正常辅助组件；没有执行重启或睡眠。
