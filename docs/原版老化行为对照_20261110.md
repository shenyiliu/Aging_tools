# 原版老化模块行为对照

基准为用户提供的 `GW_TEST`，原主程序版本 5.0.0818。以下脚本行号指 `GW_TEST_逆向研究/recovered/` 中已提取的 AutoIt 文本。脚本由独立 AutoIt-Ripper 恢复，不冒充 REA 反编译输出；原 EXE、恢复文本的对应哈希见研究目录 `evidence/recovery-manifest.json`。REA 资源及组件证据另由本轮总记录保存。

静态恢复说明代码如何写，真实执行说明某一具体环境实际发生什么。两者不能互相替代。本表不将一次软件回归、三秒播放探测或既有 BurnIn 模式 0 短测扩大为全部模块和多机型已验收。

## 配置、启动及调度

| 行为 | 原版证据 | 本轮实现与边界 |
|---|---|---|
| 队列来自 AgingSwitch，按条目顺序执行，允许重复项目 | Test.au3:18895、22536；ControlPanel.au3:17284 | 保留原条目字符串及次序，重复项目使用序号区分日志与报告。没有用项目名称去重。 |
| 启动需确认；MAIN/AgingState 与每项 Info/State 分开 | Test.au3:18886–19028 | 保留用户确认和每项状态；新实现先做整个队列依赖预检，缺项不先运行前面的重启/负载。 |
| 切项重启有条件，不是每两个项目之间都重启 | Test.au3:22536–22560 | 多项队列中，当前项及前一项都不是 Reboot，且该待运行项尚未切项重启时执行；首项不是 Reboot 也符合原分支。新实现增加可见开关，并记录已完成切项，防止重复重启。 |
| 调度接受 WAIT/RUN/STOP，END 不是 PASS | Test.au3:22545、22721、22832 | 使用单一持久结果源。结束伴随错误仍 FAIL；中止和不确定不判硬件通过。原版失败停止读取 ErrorNum 与包装器写入 Error/Num 的字段不一致，复刻版有意统一。 |
| 通过快捷方式/注册表/INI 续测 | Test.au3:18925、22547；Reboot.au3:19103 | 新实现使用有校验的检查点及当前用户登录计划任务；系统启动 GUID 未变时，重开程序不能增加重启次数。原注册表活动记录不直接并入新任务。 |
| 下次开机自动开始 | Test.au3:19555–19564、18689–18693 | 原菜单先确认“即将关机”，写 AgingInNextBoot=Y 后执行 Shutdown(4+1)，这是关机而非重启；下一次程序启动读到 Y 即点击老化并清 N，原版并无 BootId 验证。新工具“下次开机开始（等待手动重启）”只持久保存 AwaitingReboot/start 并提示用户手动重启/关机，不主动关机，这是明确差异；启动 GUID 变化后开始队列，不增加任何项目周期，也不重复安排开始。演练不执行物理动作。 |
| 引擎/视频执行中崩溃 | Test.au3:22682–22690 | 视频原版记录可能意外重启；新实现将丢失结果的执行记 Uncertain，默认停止后续队列，不自动重复压力引擎。 |
| 完成后脚本及关机 | Test.au3:22888–22900 | 保存结果后执行显式配置的脚本，再显示十秒可取消关机。新实现记录完成动作领取状态，防止恢复后重复执行。视频与完成后关机互斥由原设置规则保留。 |

## 重启、睡眠及检查

| 行为 | 原版证据 | 本轮实现与边界 |
|---|---|---|
| Reboot 耗时 | Reboot.au3:19161–19187 | 从真实重启请求前的持久时间到续测时计时，不包含前置倒计时。原版计时包含重新登录和工具启动，不能宣称为固件或内核纯启动时长。 |
| Reboot 比较均值包含本次 | Reboot.au3:19161–19187、19293–19312 | 本轮修正原先统一使用过去均值的差异；现在 Reboot 用包含本次的均值，零时长或本次/均值≥2 记异常。 |
| Sleep 比较过去均值，第二次起检查 | Sleep.au3:20688–20707、20842–20861 | 本轮补齐：第二次起检查相对过去均值异常，并检查本次用时小于设定睡眠时长；第一轮仍依赖 PwrTest 和真实进入/唤醒证据。未伪造睡眠时长或事件。 |
| 睡眠命令 | Sleep.au3:20630–20640 | S3/S4 使用 PwrTest `/sleep /c:1 /p:<秒> /h:<配置> /s:3或4`；CS 使用 `/cs /c:1 /p:<秒>`。每轮独立保存原始输出。未执行本轮真实睡眠/重启。 |
| 不支持电源模式 | Sleep.au3:20818–20823 | 系统能力不足明确拒绝；新实现还要求 S4 休眠条件和事件证据，不将不支持项改成 PASS。 |
| 暂停与继续 | Reboot.au3:19053–19091；Sleep.au3:20745–20777 | 倒计时暂停不消耗剩余时间，继续日志记录暂停秒数。真实睡眠或外部压力执行时不提供假暂停；停止只处理本任务进程树。 |
| 设备检查 | Reboot.au3:19314–19380；Sleep 对应函数 | 对基线设备实例的缺失、状态变化及总内存差超过 512 MiB 记错。当前 WMI 枚举与原 CM 枚举不是完全相同过滤接口，此差异仍需目标机样本验证。 |
| Wi-Fi 检查 | Reboot.au3:19406、19445；Sleep.au3:20970、21009 | 检查接口与可扫描热点，不要求联网；操作系统位置权限会影响扫描。 |
| 厂商风扇 | Reboot.au3:18941 起 | 原程序在重启前倒计时开始约一秒时调用所选方案 CPUFAN/<方案>/CPUFUN.cmd 并读 fanr 文件。新 Core 通过 PrepareCycleAsync 在每轮倒计时开始时并行准备（比原版触发提前约一秒），仅 Windows Reboot 有所选风扇方案才实际测量；准备有六十秒取消期限，必须等待清理。失败遵循 StopOnFail，启用失败停止时不会先执行重启。厂商驱动/脚本可能访问 EC，不能仅凭文件存在就判真实转速正常。 |

`LegacyTiming.cs` 固化了以上计时规则。新增回归覆盖 Reboot 与 Sleep 选取不同均值、Sleep 第二轮短时长检查、历史本地时间戳兼容、准备失败阻止物理动作、取消等待准备清理、显式继续时保留准备错误，以及下次开机等待、同次启动不开始、一次性恢复和演练隔离。合计 55 项 Core 测试通过，记录为 `artifacts/verification/behavior-audit-core-tests.trx`。

## 视频

原 UI 创建位置为 Test.au3:18227–18266：黑色、置顶、无边框全屏；视频宽度等于屏幕宽，区域高度为宽度×0.5625，垂直居中；WMP 隐藏播放控件并循环。P/F 按钮位置分别为 (10, 屏高−140, 220, 90) 和 (250, 屏高−140, 220, 90)，基础字号 32，开始时隐藏。点击覆盖区域后显示按钮，配置计时五秒后隐藏（19435–19439、23097–23105）。

顶部浮层由 150×36 的时间、58×36 的电池图标、90×36 的电量组成，初始 (10,6)。每分钟秒值为 1 时移动 20 像素并在边界反向；若电池电量下降且低于 90%，背景为红色，否则黑色（22770–22830）。本轮 VideoForm 已按这些静态位置/规则重建，电池来自系统真实电源状态，图标复用原 Battery 位图，未凭空生成电量。

**PlayNum 是一次进入视频老化的次数，不是视频内部循环次数。** 原版只在 `_VIDEOPLAY` 中递增（22975–22986），WMP 内部循环不再次调用该函数。原来的 C# 实现曾将播放位置回绕累计为 PlayNum，本轮已修正为一次启动记 1，RunTime1 记录本轮累计时长。

真实播放短探测使用独立 WinForms harness，WMP 实例静音，不修改系统音量；三秒后自动以 FAIL 结束，不能作为人工画面/声音通过。记录 `artifacts/verification/video-behavior-check/result.json`：WMP PlayState=3、播放位置约 2.34 秒、MediaPlayed=true、PlayNum=1、视频区域 1920×1080、P/F 初始隐藏。没有运行原 Test.exe，也没有运行正式老化队列。初次探测误传相对视频路径导致组件启动错误，纠正为绝对路径后启动通过；生产路径由工具匹配产生绝对路径。

保留的明确差异：直接 P/F 热键，Esc 关闭记中止；未在三十秒内开始播放则失败，解码错误不能按通过；计时/结果以新持久状态为准。窗口实时分辨率切换、混合 DPI、不同媒体解码器仍需交互验收。没有声称完成原版逐像素动态截图对照。

## 日志兼容

原 ViewLOG.au3:14589–14642 读取 FirstTime、EndTime、Cycles、TargetTime、Delay、AverageTime、BurnIn_Report 与 Video/PlayNum、RunTimeN；不能只输出 JSON 替代旧报告。主日志仍采用 UTF-16LE BOM INI，事件日志为独立 TAB 文本。

本轮旧日志日期对齐 `yyyy/MM/dd HH:mm:ss`，并补 FirstTimeStamp/EndTimeStamp，使用原三份执行脚本统一的本地参考 `2022/07/20 00:00:00`。以原历史 `2026/11/05 18:01:04 → 135626464` 作回归对照。原始外部引擎报告单独留存，不由复刻工具生成通过文本；演练日志必须明确 Simulation=Y、HardwarePassed=N。

## 不能从现包补出的部分

现有依赖清单显示 BurnIn 引擎和 LastUsed_0/1/2.bitcfg 存在，而 BurnInTest.exe 包装器缺失；FurMark 引擎/包装器以及 3DMark 包装器也缺失。3DMark 场景定义、语言文件和 INI 不能代替可运行引擎。允许复制组件意味着可复用实际存在的引擎、视频、资源和工具，不能把缺失文件写成已完整恢复，也不能给缺失项目制造成功结果。

原代码还包含关闭 UAC、清空系统日志、出货封装等全局动作。新工具不以执行这些副作用为 1:1 验收条件，保留明确的管理员入口、事件范围和本任务清理边界。完整运行验收仍应在各目标机型验证实际电源、驱动、引擎、停止/恢复、视频交互及长稳。
